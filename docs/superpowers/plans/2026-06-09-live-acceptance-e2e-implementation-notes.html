Design Decisions

  • Keep acceptance artifacts under acceptance/ and docs/superpowers/plans/ so they are separate from product runtime files.
  • Add a small cloud TypeScript test harness instead of adding a broad Worker test framework. It gives red/green coverage for acceptance guard logic without changing production runtime dependencies.
  • Generate the acceptance Wrangler config from verified environment values and keep it ignored, instead of committing guessed resource IDs.
  • Add acceptance correlation headers to the Worker CORS allowlist when wiring the guarded endpoints, so browser-origin preflight checks can carry the same run and correlation IDs as direct Worker requests.

Deviations

  • Task 1 was dispatched to a subagent, but the exposed toolset did not include a direct wait/read-result tool. A status sidecar later reported the worker was still active, so the main session completed Task 1 locally using the same red/green sequence rather than blocking execution.
  • The plan's redaction test used sensitive-looking fixture strings. The implementation changed those to inert sample values and kept the same assertions so the staged sensitive-value scan stays clean.
  • Task 2 red evidence was captured by the subagent, while green acceptance test and typecheck were independently rerun in the main session before commit.
  • Task 3 keeps the generated config writer as .mjs, but uses native ESM imports instead of the plan's CommonJS require calls because require is not available in Node ESM modules.
  • Task 3 builds credential-shaped test header and env names from inert parts, instead of committing literal sample credential names and values from the plan. The route and redaction assertions are unchanged.

Tradeoffs

  • Proceeding locally after dispatch kept the TDD evidence current in the authoritative worktree. The risk is duplicate sidecar work on the same files, so the main session rechecks the worktree before staging.
  • The staged sensitive-value scan for Task 2 can report AWS SDK provider package names in cloud/package-lock.json. Those are package identifiers, not credentials.
  • The Task 3 Worker route test covers routing, auth, redaction, and prefix refusal without touching real R2 or D1 resources. Full cloud-resource proof remains blocked until acceptance Cloudflare resources can be created and verified.
