Design Decisions

  • Quick Batch uses every eligible card discovered from the starting gallery, capped by the existing Gallery Limit.
  • Provider-accepted state, not click dispatch or return navigation, is the only batch progress signal.
  • Generation run state will be background-owned; the existing Sync lease remains separate.
  • Sync will reuse serialized processedIds for durable per-asset UUIDs and keep only the active conversation inventory in the existing run mirror.
  • The Grok adapter treats asset ID plus post ID as gallery identity. Conversation ID is metadata scope and is never sufficient to identify a card.
  • Agent Mode binds the one selected .react-flow__node-asset by stable node/media asset identity. The persisted post ID remains context because current Agent DOM does not expose it.
  • Submission acceptance must be new and source-scoped. Control disappearance, return navigation, unrelated progress, and stale result media remain pending.
  • Prompted Batch persists only a flat source/action checkpoint with baseline counters. Prompts, cookies, signed URLs, and composer DOM are not persisted.
  • Direct Agent starts use the conversation UUID as contextual post identity only when no gallery post hint exists, because current Agent DOM exposes no post UUID.
  • Current Saved cards bind one overlay post link to one sibling generated-media branch inside the same masonry-card wrapper. Empty image alt text is supported only for trusted generated asset URLs.
  • Video Goal uses the source-bound Agent toolbar action or the exact detail Make Video then Quick Animate path. Add Prompt and Precise Edit are excluded from Goal.
  • Recreate authority is bound to the exact owner document. Stop remains in a cancelling state until that document acknowledges cancellation or the bounded authority clear fails closed.
  • Recreate result proof uses a pre-submit signature baseline and requires one new playable result. Video proof requires fetched non-empty media bytes rather than a poster or URL alone.
  • Sync treats the authenticated conversation response as the complete Saved-entry inventory. A visible card is only an entry point and never completion proof.
  • Sync progress version 2 derives its cursor from durable per-asset receipts. A queued or attempted transfer cannot move the cursor past a missing receipt.

Deviations

  • Task 6 expanded into the shared gallery adapter after live inspection showed that current Saved links and media are siblings and generated images may have empty alt text.
  • The approved direct Video Goal action is represented by Quick Animate on current detail pages, so the runner opens the menu before checkpointing and dispatching that exact item.
  • The inventory parser remains private to the page bridge and is exercised through its request/result contract in tests/unit/bridge.test.js. A second parser test module was not created because it would require exporting a page-world implementation solely for tests.

Tradeoffs

  • A second permanent Sync ledger was rejected because it would duplicate thousands of IDs and increase Chrome storage quota and write-race risk.
  • The adapter/controller extraction adds three focused runtime files, but removes repeated selector and state logic from the 8,000-line content script.
  • Agent identity cannot re-prove the source post ID from current DOM. The adapter therefore requires exact unique asset agreement and fails closed on duplicate, disagreement, or multiple selected nodes.
  • Current sibling media is accepted only when one direct card branch resolves to one asset identity. Multiple branches fail closed rather than guessing which media belongs to the post link.
  • No permanent conversation-completion ledger was added. A reload may re-fetch an already completed conversation, then derives completion from existing processed asset IDs. This costs one read but prevents an old preview ID from hiding later sibling assets.
  • Agent and legacy detail surfaces are used only to acquire a missing conversation ID for a Saved-origin run. The old one-preview transfer fallback was removed because it could silently omit sibling assets.
