Design Decisions

  • Quick Batch uses every eligible card discovered from the starting gallery, capped by the existing Gallery Limit.
  • Provider-accepted state, not click dispatch or return navigation, is the only batch progress signal.
  • Generation run state will be background-owned; the existing Sync lease remains separate.
  • Sync will reuse serialized processedIds for durable per-asset UUIDs and keep only the active conversation inventory in the existing run mirror.
  • The Grok adapter treats asset ID plus post ID as gallery identity. Conversation ID is metadata scope and is never sufficient to identify a card.
  • Agent Mode binds the one selected .react-flow__node-asset by stable node/media asset identity. The persisted post ID remains context because current Agent DOM does not expose it.
  • Submission acceptance must be new and source-scoped. Control disappearance, return navigation, unrelated progress, and stale result media remain pending.

Deviations

None.

Tradeoffs

  • A second permanent Sync ledger was rejected because it would duplicate thousands of IDs and increase Chrome storage quota and write-race risk.
  • The adapter/controller extraction adds three focused runtime files, but removes repeated selector and state logic from the 8,000-line content script.
  • Agent identity cannot re-prove the source post ID from current DOM. The adapter therefore requires exact unique asset agreement and fails closed on duplicate, disagreement, or multiple selected nodes.

None currently. Live spend and write lanes remain approval-gated.
