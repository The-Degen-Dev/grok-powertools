Design Decisions

  • Use this HTML file beside the saved plan so implementation notes stay tied to the plan artifact.
  • Strengthen Task 1's ignore assertion from literal .gitignore line checks to git check-ignore --no-index so equivalent ignore patterns are caught.
  • Replace a long-running Task 2 spec reviewer with a narrower reviewer that did not repeat install dry-runs. The install dry-runs were already performed by the implementer and will run again in the full validation task.
  • Strengthen Task 3's CI contract test to parse workflow YAML with js-yaml instead of raw string matching. Add js-yaml@4.2.0 as a direct root dev dependency in the CI commit task so the final test does not rely on ESLint's transitive dependency.
  • Run Task 6 validation through mise exec node@24 instead of activating Node globally. This matches CI's Node 24 target without changing the user's shell defaults.
  • Create a pull request for Task 8 CI verification because the workflow's push trigger is limited to main/master; branch validation runs through the pull_request trigger.
  • Use Playwright's supported Chrome channel in CI for extension smoke tests. The PR runner provides Google Chrome, and this avoids a hung npx playwright install --with-deps chromium step while keeping Chromium-family coverage.

Deviations

  • Task 1 will not keep the plan's exact literal .gitignore assertion because the code-quality reviewer found that it under-proves the stated lockfile contract. The intent stays the same: lockfiles must not be ignored.
  • Task 2 review did not wait indefinitely on the first spec-review subagent. It was closed after timeout and replaced with a scoped reviewer to avoid blocking execution.
  • Task 3 will not keep the plan's exact raw-string CI workflow test because the code-quality reviewer found that comments or misplaced commands could make it pass falsely.
  • Task 6 added one extra commit, b8f9b80 fix: satisfy fullscreen viewer lint, because the web app could not pass local lint until togglePlay was declared before the keyboard effect that calls it.
  • Task 8 departs from the plan's assumption that gh run list --branch codex/main-cleanup-github-sync would show a push run. It did not, so a PR is created to exercise CI.
  • Task 8 departs from the original CI workflow plan by replacing the Playwright Chromium install step with google-chrome --version plus channel: "chrome" under process.env.CI. The original install step hung without producing logs.

Tradeoffs

  • The stronger git check-ignore --no-index assertion couples the test to Git behavior, but that is appropriate because the requirement itself is a Git tracking/ignore contract.
  • The replacement Task 2 reviewer avoided duplicate install dry-runs to keep the review bounded. Risk is low because Task 6 performs full local validation again.
  • Adding js-yaml creates one small test-only dependency, but it avoids a fragile hand-rolled workflow parser and matches the repository preference for structured parsers over ad hoc string checks.
  • Task 5 needs one more TDD loop after the initial commit because pure content-helper tests did not cover background's R2_BACKUP_UPLOAD persistence path.
  • Task 5 needed a second TDD loop for queued uploads: avoiding early persistence was not enough because processed IDs also need to persist after asynchronous queue success is proven.
  • Task 5 needed a third TDD loop because content could overwrite background's newly persisted UUID with a stale in-memory processed-ID set after direct upload success.
  • Task 5 needs a fourth TDD loop because direct upload still has two competing storage writers, and video candidate filtering became too strict for valid assets.grok.com/videos/... URLs.
  • Task 5 needs a fifth TDD loop because background queue-success persistence still writes from stale in-memory IDs and does not await storage durability before dropping the queue item.
  • The Task 6 lint repair was committed separately instead of amending CI or backup commits so validation-driven web cleanup stays reviewable and isolated.

Open Questions

  • Consider a separate dependency-audit task for the 6 dev-only transitive npm findings. They did not block Task 4 because npm audit --omit=dev was clean and the findings were not introduced by js-yaml@4.2.0.
  • Next.js build warns about multiple lockfiles and inferred workspace root. Build passes, but setting turbopack.root in web/next.config.ts could silence it in a separate cleanup.
