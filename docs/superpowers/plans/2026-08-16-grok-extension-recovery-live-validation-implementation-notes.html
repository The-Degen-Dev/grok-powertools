Design Decisions

DecisionReasonImpact
Use this plan-specific HTML file instead of replacing the tracked root implementation-notes.html.The root file documents an older Video/GIF Recreate goal and is historical project evidence.Both records remain intact; this file is the running record for the current recovery plan.
Allow Task 1's --evidence argument to accept inline JSON or a readable JSON file path.Task 1 describes inline JSON, while Task 9's approved command passes a file path.One CLI supports both approved call sites without creating a second tool.
Commit this notes file before runtime baseline capture.Task 1 requires the dirty baseline to contain exactly the six approved tracked runtime/test files and two protected untracked files.A docs-only commit precedes Task 1; the captured runtime patch remains exact.
Serialize lane updates with a bounded same-directory lock.An atomic rename prevents torn JSON but does not prevent two recorders from dropping each other's updates.Concurrent lane evidence survives; a stale lock may be reclaimed only after the bounded stale threshold.
Remove document-global video progress as a Prompted Batch acceptance signal.Unrelated Grok video activity could otherwise satisfy acceptance for the selected source.Acceptance now comes only from the verified composer controls or a captured same-conversation changed post.
Treat unknown Saved scope as temporary only during return polling.React may briefly leave native scope unrendered during navigation, while a detected Liked scope is definite drift.Polling can wait through loading, but restoration cannot succeed until exact All scope is positively detected.
Use worker-local single-flight ownership for download finalization.Persisted ownership turned an in-worker concurrency concern into a chain of uncancelable storage writes and repair races.Concurrent callbacks remain exactly once; restart clears ownership naturally, while durable phase markers support crash recovery.
Carry the breaker-round completion-handoff finding into Task 4.Task 4 owns completion snapshots, durability barriers, and retry classification, and its files overlap the exact race.Task 4 cannot pass until active finalizers are protected from revision handoff and incomplete complete/R2-present Dual-write operations have a retry path.
Replace shared-key completion snapshots with immutable records and bounded terminal checkpoints.Chrome storage writes cannot be cancelled. A timed-out shared-key write can settle late and overwrite newer state.Late writes are fenced by authority instead of assumed cancelled; checkpoints compact retained evidence before finite local storage can grow without bound.
Carry the final writer-authority ambiguity into Task 5 as its first gate.After five Task 4 review rounds, one narrow hydration conflict remains real and load-bearing. The protocol forbids a sixth hidden fix round.Task 5 must fail closed on duplicate claims and lease-writer mismatch before adding traversal state that depends on hydrated run authority.
Prove Saved exhaustion from a run-local identity ledger rather than processed IDs.Processed IDs describe prior extension work, not current gallery membership or R2 presence. Virtualized lists can also recycle DOM nodes.A run completes only after semantic loading is absent, no new eligible identity appears, and the stable-bottom round and elapsed-time thresholds both pass.
Keep loader detection inside the explicit Saved surface root.An unrelated page progress bar must not keep a backup running until its scan limit.A missing post-scroll Saved root resets stability and fails closed instead of widening the query to a parent or the document.
Treat inventory verification as a per-lease read-only preflight, not as processed-ID proof.Historical extension state cannot prove that an object still exists in R2, and an inventory row alone cannot prove readable bytes.Each verified canonical row must pass HEAD with positive bytes and matching media type before it can become already_present; otherwise only a 404 continues to upload.
Use one common durable-result recorder for presence hits, uploads, and failures.Separate accounting paths allowed legacy-detail presence errors to disappear and later report Complete.Both Agent and legacy-detail flows now stop on unsuccessful transfer status, count failure once, persist progress, and leave processed IDs unchanged.
Require complete observer proof before reconciliation begins.A partial, blocked, or malformed observer snapshot could otherwise reconcile a subset and return green.The CLI requires schema version 1, exact normalized UUIDs, exhausted: true, and no blocked reason before making any request.
Make reconciliation artifacts deterministic and fail-closed.DOM/API order and untrusted Worker response text must not change evidence or leak into terminal output.Classifications and redacted rows are sorted; malformed cursor or inventory shapes emit fixed codes, write no evidence, and expose no stack, path, key, or secret-shaped value.
Drive Dual-write E2E through production background code.A fixture-owned operation map and direct processed-ID write could pass while production durability was broken.The harness now dispatches through the registered background.js listener and drives production download-complete/R2-present hooks; only production code mutates processed IDs.
Define negative-workflow quiescence from controller state, not elapsed wall time.A 20 ms sleep could miss a late continuation after Stop or failure.Tests advance beyond configured deadlines, drain runtime/timer work, and require controller, transfer, return, and batch promises to be idle before stable snapshots.

Its remaining narrow writer-authority ambiguity became Task 5's first gate and is now closed. Task 5 deferred one minor timing-test precision check to final review; the runtime requires both stable rounds and elapsed time.

Tradeoffs

ChoiceAlternativeWhy
Track public implementation notes in Git and keep detailed worker artifacts in the ignored SDD workspace.Put all coordination detail in one tracked HTML file.The HTML stays readable and secret-safe; briefs, reports, and review packages remain recoverable without bloating the branch.
Execute deterministic Tasks 1-9 before any live Chrome lane.Patch and test directly against production first.This keeps cloud and credit-bearing actions behind source-bound deterministic gates.
Use immutable uniquely keyed records plus retained terminal fences.Hold mutation queues until every storage promise settles, or release timed-out same-key writes.The chosen design keeps Stop and replacement runs operable while making late writes non-authoritative. It costs more local protocol code and requires bounded compaction tests.
Require both eight stable rounds and 6000 ms before Saved exhaustion.Use only a round count, only elapsed time, or infer completion from processed IDs.The combined condition tolerates virtualization and delayed loading at the cost of a bounded quiet period before natural completion.
Cache the inventory Promise by immutable scrape-lease key.Cache only a resolved map or paginate independently for every item.Concurrent checks share one pagination pass; stop, completion, revocation, and preflight failure evict the cache.
Use an observer that shares thresholds but not extension code.Trust the extension's own traversal/completion output as the only proof.The acceptance observer independently resolves the Saved owner/scroller and captures UUIDs without clicks, navigation, media fetches, or extension APIs.
Invalidate detached fixture elements after every remount.Count remounts while allowing a cached stale node to remain actionable.Every open records current generation; disconnected or prior-generation activations fail, and observed open/submit/return arrays must match exact identity order.
