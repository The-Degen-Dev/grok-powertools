ChatGPT Images Provider Implementation Notes

Design Decisions

  • Use the narrower https://chatgpt.com/images* manifest match for V1. The design spec mentions chatgpt.com/*, but the implementation plan and V1 scope are limited to the Images route. This avoids injecting the overlay into unrelated ChatGPT pages.
  • Preserve existing Grok-compatible manifest routes, including *.x.com, *.grok.x.ai, and imagine-public.x.ai, as Grok provider routes so existing behavior is not hidden on those pages.
  • Add package allowlist coverage for new provider helper scripts because the release packager is static and would otherwise omit manifest-referenced files.
  • ChatGPT Images support now tracks the native ChatGPT Images prompt bar and native send button. The earlier extension-owned ChatGPT prompt textarea and Generate Image button were removed because they created a different workflow than Grok and duplicated the site composer.
  • Use the visible ChatGPT ProseMirror composer instead of the hidden fallback textarea. Live validation showed the hidden fallback can contain stale text while the actual visible input remains empty and the native send button stays disabled.
  • Merge provider run ledger updates by runId so the generated entry preserves the original submit timing while adding result evidence.

Deviations

  • Do not call applyProviderUi() at the exact insertion point shown in the plan. Current content.js assigns this.el after appending the overlay, so provider UI must run after this.el is assigned.
  • Guard Grok-only bridge and manager behavior on ChatGPT instead of merely hiding Grok UI controls. The plan focuses on UI gating, but pre-coding review found the current bridge, retry manager, and scraper are initialized unconditionally.
  • Depart from the plan's dedicated ChatGPT card. The accepted behavior is: type the image prompt in ChatGPT Images, click the native send button, and let the extension observe status, result delta, and provider history.
  • Read live provider history evidence from Chrome Profile 4's extension LevelDB instead of navigating to an extension page, because extension-page navigation caused confusing Chrome tab behavior during validation.

Tradeoffs

  • Narrow ChatGPT route matching means V1 will not route users from other ChatGPT pages to Images. That is an intentional tradeoff for tighter permissions and less unrelated UI injection.
  • ChatGPT Images V1 tracks native mouse submit. Keyboard submit is still a follow-up risk because the current listener observes clicks on the native send button.

Open Questions

  • Should keyboard submit on ChatGPT Images be tracked in a follow-up slice?
  • Should provider history get a small read-only diagnostics surface so future validation does not need Chrome profile LevelDB inspection?
