# Grok Power Tools v0.2.0 Release Prep Design

## Context

The current release goal is to clean up the repository, validate the working Image Recreate workflow, and publish a real `v0.2.0` GitHub release before starting short video or GIF recreation work.

The repository is currently a three-surface project:

- Chrome extension at the repo root, with raw MV3 files and no build step.
- Next.js web app under `web/`.
- Cloudflare Worker under `cloud/`.

The release target is current `main`, not any stale local branch. The old `v0.2.0-pre-release` GitHub release points at tag `v0.1.9` and must not be reused without explicit review.

## Design Choice

Use approach C: release plus future-work boundary.

This means the execution plan should publish the current working Image Recreate release and also document how short video or GIF recreation should be approached later. The next feature is not part of this release payload.

## Release Scope

The release includes the current extension, web app, and cloud worker state already merged into `main`.

Allowed release-prep changes:

- Correct release notes and user-facing release docs.
- Add or update release checklist material.
- Add packaging scripts only if packaging cannot be done reliably with existing tools.
- Record validation evidence for Image Recreate.

Disallowed changes unless validation exposes a release blocker:

- Changing Image Recreate behavior.
- Adding short video or GIF recreation UI.
- Changing Grok automation selectors.
- Merging the old divergent `feat/web-redesign` branch.
- Reworking unrelated extension, web, or cloud code.

## Repository Cleanup

The cleanup pass should:

- Confirm `main` is clean and aligned with `origin/main`.
- Fetch and prune remotes.
- Confirm there are no open PRs that should land before release.
- Inventory local branches and worktrees.
- Delete only branches proven merged and not attached to active worktrees.
- Leave `feat/web-redesign` alone unless a separate archaeology pass is requested.

Cleanup is not a license to rewrite repo history or remove unknown user work.

## Validation Gate

The release should not be published until these commands pass:

```bash
npm run test:unit
npm run test:e2e
npm run lint
npm run build --prefix web
npm run lint --prefix web
npm run typecheck --prefix cloud
```

Live Grok validation is required because Image Recreate depends on current Grok UI behavior. Local unit and mocked browser tests are not enough for this release.

The live validation should:

- Use the user's existing Chrome/Grok session.
- Operate only on the visible Grok tab with narrow probes.
- Avoid whole-profile tab enumeration, full Chrome accessibility snapshots, and loops over every tab.
- Start from `https://grok.com/imagine` or normalize the visible tab there before running.
- Reload the unpacked extension only through user action if Chrome extension permissions block automation.

Live success means:

- A reference image is selected.
- The image is actually attached to the Grok chat prompt step.
- Grok chat returns a usable final prompt.
- That prompt is transferred into Grok Imagine.
- Grok Imagine reaches a `/imagine/post/...` route or equivalent generated result view.
- Generated media is visible and openable.
- Evidence records the prompt, output URL, and relevant run status without secrets or cookies.

Live failure should stop quickly when:

- The overlay is missing.
- The tab is on the wrong route and cannot be normalized safely.
- The reference image is not attached.
- Chat does not produce a final prompt.
- The prompt is not transferred to Imagine.
- Generated media is absent, blank, or not openable.
- Chrome or the Grok tab becomes unstable.

The plan should not use long blind waits to hide failures.

## Release Package

Because the extension has no build step, the release package should be a deterministic zip built from tracked extension files only.

The package must exclude:

- `.git/`
- `node_modules/`
- `test-results/`
- `playwright-report/`
- `temp_ref/`
- local screenshots or ad hoc media
- `.env*`
- secrets, credentials, cookies, API keys, and OAuth files

The package should include the files needed to load the extension unpacked in Chrome. If a packaging command is added, it should make this file list explicit enough to review.

Preferred artifact name:

```text
grok-power-tools-v0.2.0.zip
```

The artifact can be generated outside the repo, for example under `/tmp`, to keep the worktree clean before publishing.

## Publishing Flow

Publishing should happen after any release-prep edits are merged through a PR.

Flow:

- Create a release-prep branch.
- Commit release docs, package-list, or validation-note changes.
- Open a PR with a concise semantic title.
- Wait for CI.
- Merge the PR through GitHub.
- Update local `main`.
- Confirm local `main` is clean and matches `origin/main`.
- Create tag `v0.2.0` on that commit.
- Create the GitHub release from `v0.2.0`.
- Upload `grok-power-tools-v0.2.0.zip`.
- Verify the release URL and downloadable artifact.
- Delete/prune the release branch after merge.

Do not push directly to `main`.

## Release Notes

`RELEASE_POST.md` is stale and should be corrected before the release is published.

The `v0.2.0` notes should cover:

- Image Recreate workflow.
- Prompt/history improvements that are currently in `main`.
- Auto-retry and goal reliability improvements that are currently in `main`.
- R2 or cloud backup state if included in this release.
- Installation and update steps for an unpacked extension.
- Known limitations around live Grok UI drift and manual extension reload.
- Live validation evidence for Image Recreate.

The notes should not claim short video or GIF recreation is shipped.

## Short Video And GIF Boundary

Short video and GIF recreation is a follow-up project.

The next design should build on Image Recreate but make separate decisions for:

- Input sources: local video, animated GIF, current Grok video, extracted frame set.
- Frame sampling: representative frames, motion keyframes, first and last frames, and scene changes.
- Prompt generation: Grok Imagine-specific motion prompts, not generic video model prompts.
- Motion fidelity: subject continuity, camera movement, timing, action, style, and background.
- Validation: playable/openable output media with visual relation to the reference.
- Measurement: extend or parallel the existing recreate run ledger to track prompt version, Grok UI state, input type, output URL, and quality scores over time.

This release should not add UI controls for video or GIF recreation.

## Acceptance Criteria

Release prep is complete when:

- `main` is clean and aligned with `origin/main`.
- Stale branches are either pruned safely or explicitly left alone with reason.
- All local validation commands pass.
- One live Image Recreate run is recorded with openable output evidence.
- Release notes accurately describe `v0.2.0`.
- The extension zip is built from reviewable files and contains no secrets.
- GitHub release `v0.2.0` exists at the intended commit.
- The release artifact downloads successfully.
- The local repo is clean after branch cleanup.

## Pause Criteria

Pause for user input before proceeding if:

- A local branch has unmerged work or is attached to a worktree.
- The old `v0.2.0-pre-release` needs deletion or mutation rather than leaving as historical.
- CI fails for a reason unrelated to release-prep changes.
- Live Grok validation fails on a behavior change that requires code edits.
- Extension reload requires manual Chrome action.
- A release artifact appears to contain secrets or local-only files.
- Tag `v0.2.0` already exists locally or remotely.
