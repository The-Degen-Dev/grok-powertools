Product Model

The Repair Workbench is a seven-role operator tool. Each role emits evidence before the next role can act.

1

Scanner

Reads inventory, indexes, snapshots, and selected local proof without changing cloud or browser state.

2

Classifier

Labels gaps by risk tier, proof strength, affected asset count, and repair lane.

3

Planner

Builds a dry-run plan with target rows, object keys, expected writes, and verification checks.

4

Approval Gate

Blocks all state changes until an operator approves the exact plan and scope.

5

Runner

Executes approved, idempotent actions only. The runner never broadens scope during execution.

6

Verifier

Rechecks source proof and records pass, fail, blocked, and unproven states.

7

Ledger

Appends run history, inputs, approvals, writes, verification results, and residual gaps.

Main Flow

The default path is read-only until the approval gate. Every write path must return to verification and recordkeeping.

Data And Source Topology

The proof ladder is ordered by durable evidence. Cached public URLs are hints, not proof.

1. R2 object Direct object existence, size, content type, checksum, and key prefix are the strongest cloud proof.
2. D1/index row Useful for discovery and mapping, but weaker than object proof.
3. Metadata snapshot Provides saved prompts, prompt history, processed IDs, and backfill manifest context.
4. Verified local file/object Accepted only when the operator selects or verifies it as a source artifact.
5. Live Grok through existing Chrome Gated repair input for gaps after R2 import proof exists.

Research Lessons Embedded In The Tool

The interface should make these lessons visible as constraints, not buried in implementation notes.

Direct R2 consistency

Trust direct object reads and HEAD checks over UI cache state or old public URLs.

Conditional R2 writes

Writes must be conditional and scoped to avoid overwriting newer or already-restored objects.

Append-only repair ledger

Every plan, approval, write, verification, and residual gap becomes durable run history.

Idempotent actions

Retries should not create duplicate rows, duplicate objects, or conflicting canonical links.

Read-only check before repair

Repair begins only after the Workbench proves the current state without changing it.

Cached public URLs are not proof

They can suggest an asset existed, but cannot prove current ownership, durability, or byte identity.

Operator Notes

Short constraints that keep the Workbench in repair mode instead of turning it into a hidden migration script.

Fail closed

Missing auth, missing identity, missing cursors, or uncertain proof stops the run.

Small approvals

Approve a bounded asset set or row set, not a broad class of future writes.

No proof laundering

A weaker source cannot silently promote itself to stronger proof.

Every action returns to proof

The final screen is not success copy. It is verification evidence and remaining gaps.
