Production R2 Vault Audit Implementation Notes

Running execution notes for docs/audits/2026-06-26-production-r2-vault-system-audit/. This audit is read-only against production and records blockers instead of repair work.

Design Decisions

  • The evidence folder keeps the approved plan date in its path, 2026-06-26, while manifest.json records the actual execution start date, 2026-06-27.
  • The audit was moved to branch codex/production-r2-vault-audit from the existing audit-design commit because the previous branch name, codex/chatgpt-images-design, no longer described this work.
  • The user approved moving from spec and implementation planning into Codex Goal execution before this audit run. The runner still treats production identity proof as a hard gate before raw inventory.
  • Subagent review tightened preflight by requiring authenticated R2 bucket/prefix proof and D1 schema proof before raw R2 inventory.
  • The raw wrangler whoami output is not persisted. The audit records only the expected account ID and a structured summary of scope classes so the broad-credential blocker is evidenced without storing account email or token text.
  • The user explicitly approved the currently authenticated broad Wrangler token for remote D1 SELECT-only audit reads. The runner now requires AUDIT_APPROVE_BROAD_WRANGLER_SELECT_ONLY=1 and records that approval in logs/d1-broad-token-select-only-approval.json; production writes remain forbidden.
  • Subagent safety review found that raw Wrangler D1 stdout could be persisted before row-level redaction. The runner now disables raw D1 command persistence, stores only stdout hash/byte count/row count/metadata, and enforces single-statement SELECT SQL before Wrangler is invoked.
  • Subagent safety review also broadened prompt/private-text key redaction to cover kebab-case and snake_case metadata keys such as prompt-text, prompt_text, negative-prompt, and raw-prompt.
  • The R2 runner now writes a listing checkpoint before object-head enrichment and uses bounded concurrency for HeadObject. This preserves full coverage while avoiding the earlier serial-head bottleneck that produced no artifact for several minutes.
  • The R2 hash runner now resumes from existing r2-media-hashes.jsonl rows and hashes remaining media in small batches with bounded concurrent streams. This preserves full byte-hash coverage while allowing an interrupted hash run to continue without discarding completed hash rows.
  • Redaction was corrected to preserve storage identifier fields such as key, objectKey, and canonical_object_key. The earlier broad key redaction made R2/D1 reconciliation evidence unusable. Secret-like fields such as API keys, access keys, tokens, cookies, signatures, signed URLs, and prompt text remain redacted.
  • Live Grok inspection uses the existing visible Chrome window only. Peekaboo showed no visible grok.com/imagine/saved or Grok Vault window, so the audit recorded a live-Grok blocker instead of broad-scanning tabs or navigating unrelated Chrome windows.
  • After the user confirmed the only open Chrome window was grok.com/imagine/saved, Computer Use verified the selected Chrome tab, visible Grok Saved route, page-injected Grok Power Tools overlay, and Grok Vault toolbar popup. The live-Grok subsystem is now verified as a read-only spot-check.
  • Subagent reconciliation review found that D1/Worker exact-key gaps should be split by path semantics: legacy date-folder objects are not indexed by the current D1/Worker path, while canonical media/by-asset objects absent from D1/Worker remain unresolved raw-R2-only evidence. The report now describes those separately and avoids calling all deltas missing media.
  • Subagent reconciliation review also found that metadata-reference and local/R2 deltas should not be described as full completeness failures. The report now treats metadata as reference coverage and local/R2 as SHA-256 overlap against the scanned macOS corpus.
  • The stricter canonical-index goal adds a second-stage local canonicalization pass. Raw exact-key rows are written to ignored private/local-canonical-index.jsonl; committed artifacts contain counts, status totals, and object-key hashes only.
  • The local canonicalizer applies the accepted duplicate rule: same SHA-256 plus an accepted identity-link signal can classify an alternate or mapped duplicate; same SHA-256 alone stays needs_human_review.
  • Live Grok Saved browser control is now constrained to the active Chrome front-window tab only. The safe path is narrow active-tab JavaScript against the visible https://grok.com/imagine/saved page; do not use all-tab discovery, full-window accessibility snapshots, or DevTools page lists for this dataset.
  • The Grok Saved page uses an internal main gallery scroller rather than window scroll. The verified scroller is the large content container at the right of the sidebar, with clientHeight=1070 and scrollHeight=7029 in the current session.
  • The Saved capture script writes raw visible card data only to ignored private/grok-saved-current-inventory.jsonl and writes committed evidence only as counts and hashes in inventory/grok-saved-current-summary.json and logs/grok-saved-active-tab-capture.json.
  • The Saved capture script now merges with an existing private inventory by candidate signature. This prevents a later memory-guarded early stop from shrinking a better previous partial inventory.

Deviations

  • The audit generated a blocked current-state report before completing downstream inventory phases. This does not relax final success criteria; it preserves the exact hard-gate state for handoff.
  • The R2 phase was interrupted before artifact writeout because the user requested a safe pause before restarting the Mac. Resume from r2; do not treat the interrupted run as evidence.
  • A later R2 attempt was also interrupted before required artifact writeout so the runner could be adjusted to write a checkpoint and use bounded HeadObject concurrency. Do not treat that interrupted run as evidence.
  • The first successful listing/hash attempt wrote partial hash rows, then was interrupted so the runner could become resume-safe and use bounded hash concurrency. The existing rows are retained and the next r2 run must finish the remaining hash rows before the hash subsystem can be considered verified.
  • The redacted-key R2 artifacts from the interrupted runs were deleted after the storage-key redaction bug was found. The next R2 run must regenerate raw R2 evidence from scratch.
  • The report generator was tightened after subagent review to avoid unsafe claims: no clean production verdict, no required-metadata-loss claim from prompt-sidecar reference absence, no local corpus completeness claim, and no deletion recommendation for duplicate hash groups.
  • The final live-Grok inspection did not attempt a full Saved scrape or generation. It records visible route, extension status, cloud settings, and popup status only.
  • The canonicalization pass uses a separate script, scripts/build-local-canonical-index.mjs, instead of adding a mode to the original validated audit runner. This keeps the original read-only inventory runner stable while adding a narrower post-audit stage for the stricter goal.
  • The canonicalization pass reuses the existing same-day R2/D1/Worker/local/metadata artifacts instead of rehashing all production media again. Full current-state proof still requires either a fresh approved R2 hash rerun or accepting the existing hash snapshot as the read-only source artifact for this pass.
  • The bundled Chrome controller connected, but browser.tabs.selected() did not expose the focused user tab. I did not call browser.user.openTabs() because that would be whole-profile tab discovery on a Chrome profile with many tabs. Active-tab Chrome scripting was used instead.
  • The current Saved browser artifact is a partial grid inventory, not an authoritative logical Saved inventory. Bounded traversal captured 821 unique grid candidates, but the run stopped on the memory guard and the grid did not expose /imagine/post/{uuid} identifiers.

Tradeoffs

  • The secret scan has expected false positives in policy prose, redaction code, and root test names that mention cookies without containing cookie values. Manual review found no raw keys, bearer tokens, signed URLs, cookies, passwords, or private prompt dumps in current audit artifacts.
  • The local canonical index is useful for classification and gap analysis before Grok Saved enumeration is available, but it is still partial. D1 asset IDs, R2 keys, hashes, source URL hashes, and prompt sidecar links are evidence fields; they do not replace authoritative grokPostId identity.
  • The safe Grok Saved strategy is bounded viewport stepping: capture one visible gallery slice, scroll the main gallery container by less than one viewport, wait briefly, capture the next slice, and stop on memory or route guardrails. A one-step probe moved the main scroller from 0 to 802, loaded only a small next slice, then restored the position to 0.
  • The Saved grid appears lazy-loaded or virtualized. Longer scroll passes expanded the scroll range and sometimes shifted scroll position backward after new batches loaded. Continuing blindly would increase Chrome pressure without proving completion, so the report keeps Grok Saved status partial.
  • A narrow resource-path probe found only media asset paths and /api/log_metric; it did not reveal a Saved-feed API path suitable for a safer full enumeration.

Open Questions

  • Authoritative current Grok Saved inventory is no longer blocked on browser control, but it is still incomplete. Current evidence is a partial grid scrape with 821 unique candidates, 1027 unique media URL hashes, and 694 unique media UUID hashes. Do not claim current Grok Saved completeness until traversal reaches a verified end state and logical identity is captured.
  • The Saved grid did not expose grokPostId values. Detail-page capture or another identity source is required before using Grok Saved as authoritative logical identity. Opening detail pages may require explicit approval because the objective prohibits route mutation during browser work.
  • Current local canonical index artifacts: raw ignored private/local-canonical-index.jsonl, redacted reconciliations/local-canonical-index-summary.json, redacted reconciliations/canonical-gap-report.json, and redacted report-canonical.md.
