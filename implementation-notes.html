Decisions And Tradeoffs

Decision Reason
Add video/GIF as a parallel media mode The image path is working and has image-specific validators. A parallel mode lets shared helpers stay covered while avoiding regressions in Image Recreate.
Do not accept "submitted" as success Prior recreate work showed that a submitted prompt can still produce a stale, broken, or wrong media result. Completion requires playable video proof.
Write video/GIF spec before code Added docs/superpowers/specs/2026-06-24-video-gif-recreate-design.md after live discovery confirmed Video mode controls and current quota state.
Resolve Grok post URLs inside the Grok page context recreateWorkflowContent.js now extracts og:video from trusted Grok post URLs and fetches the resulting video through the same public/background/page-cookie media path used for authenticated Grok media.
Use a lightweight run ledger, not a separate evaluation platform Background stores best-effort gptRecreateRunLedger entries with prompt version, source hash, output URL, output hash when available, phase, and error/status. Data URLs are not stored.
Keep Image Recreate as the default path Image mode still uses the original marker, image upload validation, and image result checks unless a normalized reference has kind: video.
Trust Grok generated video CDN output Live Grok Imagine generated video surfaced as assets.grok.com/.../generated_video.mp4?cache=1, not only as imagine-public.x.ai/share-videos. The trusted video URL helper now accepts authenticated assets.grok.com MP4/WebM/MOV files and fetches them through the page-cookie bridge.
Sample local video references when browser APIs allow it Local MP4/MOV/WebM references now probe duration and dimensions and use a bounded browser video/canvas sampler to build a JPEG contact sheet with representative sample times. Unsupported environments mark frameSamplingLimited instead of failing the recreate run.
Recover after Grok post navigation closes the submit message Grok can navigate from /imagine to /imagine/post/... while the content script is awaiting result validation. If Chrome reports the async message channel closed, the background now waits for the post URL, reinjects the recreate scripts, and validates the opened post media before deciding success or failure.
